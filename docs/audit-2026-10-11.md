## Constats de sécurité encore ouverts

- Supabase signale `public.spatial_ref_sys` avec RLS désactivé. Cette table est fournie par PostGIS ; ne pas activer RLS ou déplacer l'extension sans test de régression géospatiale.
- Les extensions `citext`, `pg_trgm`, `postgis`, `vector` et `pg_net` sont dans `public`. Leur déplacement doit respecter les contraintes de relocatabilité et les dépendances.
- Le linter signale encore 66 fonctions `SECURITY DEFINER` exécutables par `authenticated`. Ce signal ne permet pas de conclure qu'elles sont toutes vulnérables : beaucoup sont des RPC métier prévues. Il faut les tester une par une contre IDOR/BOLA, identité manquante, permissions admin, compte suspendu, idempotence et validation des montants.
- Les alertes d'index inutilisés sont informatives et ne justifient pas une suppression automatique sans mesure de charge réelle.

## Constat de reproductibilité — priorité critique

La base distante contient 243 migrations, mais la recherche dans le dépôt ne retrouve pas la migration initiale `initial_marketplace_core_schema` ni le texte SQL des migrations historiques. Le dépôt n'est donc pas encore démontré comme capable de recréer une base vide de manière déterministe. Il faut récupérer/synchroniser l'historique SQL complet, ou créer et valider un snapshot de schéma de référence plus une stratégie de bootstrap explicite, avant toute installation neuve ou restauration.

## Contrôles de performance

- Il signale encore de nombreux index inutilisés, notamment sur les modules secondaires. Ne pas supprimer en masse : certains peuvent être utiles après activation des modules ou sous charge.
